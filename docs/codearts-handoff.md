# CodeArts码道与华为云交接清单

本文件对应用户提供指南§1.1、§4.6、§11.2和§18的工程留证要求。当前代码由Codex实现，尚无CodeArts码道调用、华为云部署或三家机构试用记录。以下是接手项目后可以真实执行的任务；任务清单本身不计作工具使用证据。比赛名称、报名时间和正式材料格式仍应以团队参加的当届官方通知为准。

## 先交接可运行项目

团队导入 `ArtifactHealthRecord/`，首先读取 `README.md`、上级 `AGENTS.md`、`docs/api-contract.md`、`docs/guide-implementation-matrix.md` 和 `docs/standards-verification.md`。保留已有实现及明确的能力边界；不要为了展示智能体调用而重新生成整个项目。

| 交接对象 | 文件或目录 | 接手时应核对 |
| --- | --- | --- |
| Python与前端环境 | `environment.yml`、`requirements.txt`、`requirements-ai.txt`、`frontend/package-lock.json` | Conda解释器路径、依赖版本、前端构建；不创建`.sh`启动器 |
| 业务与权限 | `backend/ahr/`、`tests/test_workflow.py`、`tests/test_integrity.py` | 机构隔离、角色限制、方案版本、审核身份、原始文件及证据链 |
| 前端工作台 | `frontend/` | 病历表单、原图坐标标注、草案编辑、会诊及导出，记录实际浏览器结果 |
| AI与评估 | `ai/`、`scripts/`、`ai/DATA_ACCESS.json` | 未取得真实权重时返回人工处理；合成冒烟指标不进入真实效果表 |
| 资料与标准 | `data/knowledge/`、`docs/sources.md` | 37条摘要、4条甘肃公开案例、完整授权病例0份、图符尚待核验 |
| 部署配置 | `.env.example`、`backend/ahr/config.py`、`backend/ahr/storage.py` | 本地SQLite/文件与RDS/OBS配置分开；Redis当前用于检索缓存 |

在项目目录使用已有Python入口：

```text
python3 run.py doctor
python3 run.py test
python3 run.py build
python3 run.py serve
```

新机器首次安装可运行 `python3 run.py setup`；需要训练依赖时使用 `python3 run.py setup --with-ai`。记录运行时的Python、Conda环境、依赖、开始结束时间和完整测试结果。测试若受到容器或沙盒跨线程能力限制，应记录环境原因及实际重跑环境，不把超时写成通过。

## 按实际任务保留码道使用证据

用团队自己的真实账号安装并登录码道，再导入项目。以下每项都应选一个尚未完成或确需改进的真实工作，保存输入、输出、代码差异、人工审查和执行结果。已经完成的功能可以让码道审查，但应如实记为审查，不追溯宣称由它生成。

| 阶段 | 可执行任务 | 验收与应保留材料 |
| --- | --- | --- |
| 需求理解 | 根据指南和本项目矩阵，拆分“规范图符核验”“正式档案字段补齐”“授权病例导入”等任务，明确前置资料 | 真实会话记录、任务清单、需求与验收项对应表；待外部资料项仍标待补 |
| 设计 | 阅读现有API和数据库后，为一个选定任务提出兼容设计；说明保留哪些代码、改哪些接口 | 设计文档、输入输出例子、版本/数据迁移安排及团队审查意见 |
| 代码生成 | 在约定的单个模块内补一个确定功能，例如授权病例导入的字段与来源校验 | 对应会话、实际差异、测试和经授权的数据小样；不能把原有代码改名作为新增贡献 |
| 项目构建 | 调用现有Python入口完成环境检查、后端测试和前端构建 | 真实命令、退出码、依赖版本、构建产物；保留失败及修复过程 |
| 问题修复 | 选择实际出现的问题，先记录复现，再让码道定位并提出最小修复 | 复现输入、修复差异、针对性回归及人工核对；不制造或伪造历史失败日志 |
| 部署上线 | 在已配置的团队华为云资源上部署当前确认版本，验证数据库、缓存、对象存储和整条业务链 | 实际资源信息、部署日志、健康检查、脱敏界面截图、失败回退验证和公网地址 |

可以直接交给码道的首个审查任务：

> 先读取README、docs/api-contract.md、docs/guide-implementation-matrix.md以及项目约定。审查当前方案提交与审核路径，列出版本一致性、独立审核身份和引用校验的实际调用链。只新增或修改tests目录中的必要回归测试，先说明发现及预期行为，不更改鉴权规则或删除失败测试。使用Conda环境和python3 run.py test，输出真实执行结果与仍需云端验证的内容。不要创建.sh脚本，不改data/knowledge的来源事实，不编造模型准确率或专家签字。

若该任务没有发现新问题，正常记录“审查通过及测试结果”。无需为了形成展示材料虚构新功能或缺陷。

## 云资源接入按实际用途验收

本项目的环境变量均以 `AHR_` 开头，准确字段以 `.env.example` 为准。秘密仅通过部署环境注入，截图中隐去凭据。不要把指南中的未加前缀变量直接当成本项目配置。

| 服务 | 实际配置与验收任务 | 当前边界 |
| --- | --- | --- |
| RDS PostgreSQL | 配置 `AHR_DATABASE_URL`；初始化空数据库；保存病历、方案、会诊；模拟两个会话并发更新/提交，验证事务及版本冲突 | SQLite本地结果不能替代PostgreSQL并发测试；正式已有库需迁移方案 |
| Redis | 配置 `AHR_REDIS_URL`；同一案例检索两次核对缓存命中；停止服务确认回退；检查键过期 | 当前用途为检索缓存，会话在数据库，任务不是Redis持久队列 |
| OBS | 配置 `AHR_STORAGE=obs` 与 `AHR_OBS_*`；上传一张有明确许可的测试图；下载原件比较SHA-256；验证缺失对象和权限失败 | 官方SDK集成代码尚无真实桶凭据联调证明 |
| MaaS兼容接口 | 配置 `AHR_LLM_BASE_URL`、`AHR_LLM_API_KEY`、`AHR_LLM_MODEL`；获准发送的数据才启用 `AHR_ALLOW_EXTERNAL_MODELS=true`；检验失败回退和引用ID | `is_demo`标签不能绕过发送授权；模板回退不算成功调用在线大模型 |
| ModelArts或训练实例 | 仅使用有许可、按文物/遗址分组的数据；保留训练清单、权重哈希、独立评估及失败样本 | 合成训练仅用于工程冒烟，真实六类指标当前为空 |
| ECS与公开访问 | 部署构建后的前端和API；核对 `/api/v1/health`；从目标访问环境完成登录、上传、草案、审核与导出 | 本地HTTP可打开不算公网Demo；上线后再记录实际URL及访问时间 |

生产配置使用 `AHR_ENV=production`、`AHR_DEMO_MODE=false`，首次账号密码通过 `AHR_BOOTSTRAP_PASSWORD` 注入。使用独立生产runtime和数据库；演示库已经含默认账号时，仅改环境变量不会自动删除这些账号。
